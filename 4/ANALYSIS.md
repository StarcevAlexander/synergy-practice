# Кейс-задача № 4 — Анализ ИС WEB-архитектуры и реализация WEB-приложения

## 1. Анализ имеющихся на рынке ИС WEB-архитектуры

Информационные системы, построенные по **WEB-архитектуре**, работают по схеме
«тонкий клиент (браузер) — сервер приложений — сервер базы данных». Пользователю
не требуется устанавливать ПО: вся бизнес-логика и данные находятся на сервере,
а взаимодействие идёт по протоколу HTTP/HTTPS.

### Обзор представленных на рынке систем

| Класс ИС | Примеры | Возможности | Применение в компании |
|----------|---------|-------------|------------------------|
| CRM | Bitrix24, amoCRM, Salesforce | учёт клиентов, воронки продаж, аналитика | продажи туров, история обращений |
| ERP | 1С:Предприятие (веб-клиент), SAP, Odoo | финансы, склад, кадры, документооборот | бухгалтерия и управление турагентством |
| Системы бронирования | Booking, Amadeus, «Тур-агент» | поиск, бронирование, оплата онлайн | подбор и продажа туров |
| BI/аналитика | Power BI, Yandex DataLens, Metabase | дашборды, отчётность | анализ выручки по направлениям |
| Порталы/CMS | WordPress, Tilda, 1С-Битрикс | сайт-витрина, заявки | каталог туров и форма заявки |

### Преимущества WEB-архитектуры
- Централизованное обновление — нет необходимости переустанавливать клиент.
- Кроссплатформенность — работает в любом браузере и на мобильных устройствах.
- Масштабируемость — сервер приложений можно горизонтально масштабировать.
- Единая точка хранения данных и резервного копирования.

### Недостатки/риски
- Зависимость от сети и доступности сервера.
- Повышенные требования к безопасности (HTTPS, защита от XSS/SQL-инъекций).
- Нагрузка на сервер при большом числе пользователей.

### Варианты использования в турагентстве
Витрина с каталогом туров, онлайн-приём заявок, личный кабинет клиента,
интеграция с платёжными системами, отчётность для руководителя.

## 2. Реализованное WEB-приложение

В задании предложен стек **Delphi 10.2 + IIS + MS SQL Server**. Поскольку
Delphi/IIS — проприетарная Windows-среда, для воспроизводимости реализован
**архитектурно эквивалентный** WEB-проект на Python/Flask по той же трёхзвенной
схеме. Для MS SQL Server приложена готовая схема `schema_mssql.sql`.

```
Браузер  ──HTTP──>  Сервер приложений (Flask/WSGI ≈ IIS+ISAPI)  ──SQL──>  БД (MS SQL Server / SQLite)
```

**Функции приложения:** каталог туров, страница тура, форма заявки, список заявок.

### Запуск
```bash
pip install flask
python app.py
# Открыть http://127.0.0.1:5000
```

### Соответствие требованиям задания
- WEB-архитектура (трёхзвенная) — да.
- Хранение данных в БД — да (SQLite для локального запуска, MS SQL Server через `schema_mssql.sql`).
- Тема на выбор — «Турагентство».

### Файлы
- `app.py` — серверная часть (роуты, работа с БД).
- `templates/` — HTML-шаблоны (представление).
- `schema_mssql.sql` — схема БД для MS SQL Server.
